Pola Akses Data

1
Baca data (umum)Halaman → db.js → Supabase browser client (anon key) → tabel via RLS. Contoh: getInventory(), getTransactionsAktif().
2
Tulis data (umum)Halaman → db.js → sisipUserId() menyisipkan user_id (owner tenant) → insert/upsert → RLS access_own_or_owner memvalidasi. Contoh: updateInventory(), tambahTransactions(), tambahLogs().
3
Operasi khususHalaman → db.js → supabase.rpc(...) → fungsi SQL SECURITY DEFINER (validasi role di dalam body). Contoh: listOwners(), setRole(), getLoginLogs(), buatIDUnik().
4
Operasi sensitifHalaman → db.js → fetch("/api/...") → route server pakai service role (bypass RLS, validasi role manual). Contoh: login, register, kelola user, hapus semua data.
5
Pengaturan lokalgetSetting()/setSetting() baca-tulis localStorage (rentalpro_settings) lalu sinkron ke tabel settings (per user). getSettingTenant()/setSettingTenant() baca-tulis milik OWNER tenant (staf ikut nilai owner).
Catatan penting: Semua tabel bisnis memakai kolom user_id = id OWNER tenant. Staf (cs/gudang) menulis dengan user_id = id owner-nya (via getOwnerIdAktif()), sehingga data satu tenant terkumpul di satu pemilik.
